# Passim 手机端与 Agent 路线

> 日期：2026-11-11  
> 状态：实施建议草案。产品方向已记录，具体工作仍需拆分规格与验收，不代表已实施或已安排上线时间。

方向依据：[手机端优先与外部 Agent 接入](mobile-first-agent-direction.md)。延续已有个人云、外部 Agent 和受控执行的思路，把近期投入集中到手机端可见、可用、可管理的体验。

## 阶段 A：做完整一个手机使用场景

**范围**
- 选择一个已有模板支持的样板服务与目标用户。
- 梳理安装或连接节点、部署、实际使用、分享或导出配置、异常恢复的完整路径。
- 设计手机首页、服务入口和任务详情；复用现有 Go API、Expo、任务与 SSE。
- 记录当前实现与缺口，不先扩展大量新服务或重写客户端。

**验收**
- 用户离开聊天后能找到任务进度与结果入口。
- 完成态能说明服务是否经过实际可用性验证。
- 切换网络、重进 App 后可恢复权威状态；缓存有更新时间。
- 常用操作不依赖再次询问 Agent。

## 阶段 B：补齐统一记录与可信操作边界

**范围**
- 将用户目标与底层任务、资源、事件关联。
- 手机、Web、MCP 使用一致的状态记录，显示发起者和变更结果。
- 设计按节点与能力限制的 Agent 授权、服务端批准、撤销与审计。
- 补充幂等、重试、重启恢复、重复批准和过期批准的测试。

**验收**
- Agent 与手动操作均可追溯，不依赖聊天记录推断执行结果。
- 只读授权不能调用写操作；批准与实际执行的动作和目标一致。
- 拒绝、过期、撤销后不会继续执行尚未获准的操作。
- 任务完成与服务健康分别显示。

## 阶段 C：降低 Agent 接入门槛

**范围**
- 强化现有 stdio MCP 的配置、错误处理和稳定性。
- 设计手机端“连接我的 AI”流程，并选择目标客户端逐个验证。
- 在阶段 B 的权限边界基础上评估远程 MCP、HTTPS、认证和网络可达性。
- 明确桥接进程或远程入口由谁运行，如何安全保存凭据和恢复连接。

**验收**
- 用户能看见连接对象、节点范围、权限、近期活动并撤销。
- 不要求通过聊天传递管理员凭据。
- 区分协议握手、网络可达、身份验证和实际任务成功。
- 不依赖手机后台常驻，也不把临时云端测试环境当作可靠托管。

## 阶段 D：持续维护与日常体验

**范围**
- 提供有去重和直接入口的异常、待决定及重要完成通知。
- 按样板服务补充备份、迁移、更新和恢复体验。
- 继续收敛手机端常用操作，保留 Web 高级管理和恢复入口。

**验收**
- 通知描述真实状态，不泄露敏感配置，不把已发送当成用户已看见。
- 节点离线、Agent 断开和服务异常有明确区分与恢复建议。
- 以实际使用、任务恢复和维护耗时观察效果，不预设未经验证的数值指标。

## 后续评估

以下方向保留，但不与首个闭环同时展开：

- 完整的第一方文件、照片、影音体验。
- 手机内置系统级连接及原生 VPN 引擎。
- NAS、家用服务器和资源受限路由系统适配。
- 云资源采购、更多应用模板和多用户家庭共享。

每项都需明确数据位置、权限、平台限制、维护责任与退出方式。用户可继续使用第三方客户端、标准协议和可导出的配置。

## 文档与工程要求

先更新对应 API、任务、手机端、MCP 或权限规格，再实施和测试。核对旧文档的阶段名称与实际代码，不直接把计划标为完成。

本路线不修改现有接口，也不要求一次性移除 Web 功能。涉及网络暴露、凭据、数据迁移或高影响操作的方案须先明确安全和恢复边界。
